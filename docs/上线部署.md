# 智能客服系统 上线部署指南（网页版）

> 目标：把本系统真实跑在公网（浏览器可访问）。后续可在此基础上接入微信公众号客服。
> 前置：云服务器 + 域名 + HTTPS。LLM 已用阿里云百炼（国内直连），部署在国内服务器无需翻墙。

---

## 1. 部署形态

```
用户浏览器
   │ HTTPS
   ▼
nginx (443, 反向代理 + TLS 证书)
   │
   ▼ 127.0.0.1:8001
FastAPI (uvicorn)  —— 同时托管前端静态文件 + API
   ├─ 语义缓存 SQLite · 元数据库 SQLite
   ├─ Redis (缓存/任务状态, 可选, 没有则降级)
   └─ Celery worker (异步 ETL, 可选, 没有则同步 ETL)
        └─ LLM 阿里云百炼 (qwen3.7-flash)
```

单机即可：1 台 2核4G 云服务器跑全部。

---

## 2. 前置准备

| 项 | 说明 |
|---|---|
| 云服务器 | 阿里云/腾讯云 ECS，**Ubuntu 22.04**（2核4G，带宽 3-5Mbps） |
| 域名 | 如 `kefu.example.com`（国内服务器需 **ICP 备案**，约 1-2 周） |
| HTTPS 证书 | 域名解析到服务器后，Let's Encrypt 免费申请（`certbot`） |
| 服务器安全组 | 放行 22(SSH)、80(HTTP)、443(HTTPS)；8001 不需要对公网开放 |

> 备案期间可先用 `http://<服务器公网IP>:8001` 做内测（安全组临时放行 8001）。

---

## 3. 方案 A：单机 systemd + nginx（推荐）

> **Redis / Celery 必须稳定常驻**，不是可降级项。系统的"降级"只是异常兜底（Redis/Celery 挂掉时服务不崩但功能受限），**正常部署要让它们一直跑**：
> - Redis：`sudo systemctl enable --now redis-server`（或 Docker，见 §4）。
> - Celery worker：`sudo systemctl enable --now fin-agent-worker`（systemd 单元，见 §3.4）。
> 部署完成后用 `systemctl status redis-server fin-agent-worker` 确认两者 active。

### 3.1 服务器初始化

```bash
# Ubuntu 22.04
sudo apt update && sudo apt install -y python3.12-venv python3.12-dev nodejs npm redis-server nginx git
sudo systemctl enable --now redis-server

# 获取代码
sudo mkdir -p /opt && sudo chown $USER /opt
git clone <你的仓库> /opt/kefu && cd /opt/kefu
```

### 3.2 后端依赖 + 前端构建

```bash
cd /opt/kefu
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
# 若缺少 bge 模型: 把 models/ 目录一并拷贝到服务器 (离线加载)
cd frontend && npm ci && npm run build && cd ..
```

### 3.3 生产配置 `.env.prod`

```bash
cp .env.template .env.prod
# 按模板填写, 关键项:
#   APP_ENV=production
#   LLM_PROVIDER=deepseek
#   DEEPSEEK_API_KEY=<阿里云百炼 key>
#   DEEPSEEK_API_BASE=https://<你的工作空间>.maas.aliyuncs.com/compatible-mode/v1
#   DEEPSEEK_MODEL=qwen3.7-flash
#   CHEAP_MODEL=qwen3.7-flash
#   JWT_SECRET=<随机长字符串>   (鉴权密钥, 务必改)
#   ADMIN_PASSWORD=<强密码>     (登录密码)
#   REDIS_HOST=127.0.0.1
```

### 3.4 systemd 服务

复制 `deploy/fin-agent.service` 和 `deploy/fin-agent-worker.service` 到 `/etc/systemd/system/`，注意把里面的路径/用户改成实际值：

```bash
sudo cp deploy/fin-agent.service deploy/fin-agent-worker.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now fin-agent fin-agent-worker
systemctl status fin-agent
```

### 3.5 nginx + HTTPS

```bash
# 复制 nginx 配置 (把 server_name 改成你的域名)
sudo cp deploy/nginx.conf /etc/nginx/sites-available/kefu
sudo ln -s /etc/nginx/sites-available/kefu /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

# 申请免费 HTTPS 证书
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d kefu.example.com
```

### 3.6 验证

```bash
curl -s https://kefu.example.com/health                    # {"status":"ok",...}
curl -s https://kefu.example.com/                          # 返回前端页面
# 浏览器打开 https://kefu.example.com → 登录(admin/你设的密码) → 对话
```

## 4. 方案 B：Docker（可选）

```bash
cd /opt/kefu
# Dockerfile 已适配当前架构 (构建前端 + FastAPI 单端口 + Celery worker)
docker compose -f docker-compose.yml up -d redis
docker build -t kefu-app .
docker run -d --name kefu-api --env-file .env.prod -p 127.0.0.1:8001:8001 kefu-app uvicorn src.api.main:app --host 0.0.0.0 --port 8001
docker run -d --name kefu-worker --env-file .env.prod --network host kefu-app celery -A src.celery_app worker --loglevel=info
# nginx 同上, 反代到 127.0.0.1:8001
```

> Docker 镜像较大（bge 模型 + 依赖），首次构建慢。无 GPU，无需 nvidia-docker。
> 推荐用 `docker compose up -d --build` 一键起 redis + api + worker（`docker-compose.yml` 已配好，三者都常驻、重启自恢复）。

## 附：用自己电脑当服务器（内网穿透）

适合**自测 / 演示 / 内网使用**；给真实外部用户用不推荐（上行带宽有限、断电断网即挂）。

### 前提与限制
- 家用宽带无公网 IP → 必须**内网穿透**。
- 家庭宽带**无法 ICP 备案**（备案要求服务器在 IDC）→ 域名若走国内 80/443 需绕开：用穿透服务商域名 / Cloudflare Tunnel / IP 直连。

### 方式一：cpolar（国内，最快演示）
```bash
# 在电脑上装 cpolar 免费版
cpolar authtoken <你的token>
cpolar http 8001
# 得到一个 https://xxx.cpolar.cn 临时域名, 浏览器即可访问
# 付费版可绑定自己的域名
```
> 需先按 `docs/上线部署.md` §3.2-3.3 在本机装好依赖、构建前端、配好 `.env.prod`，然后 `python run.py --daemon --celery`（或 `docker compose up -d`）。

### 方式二：Cloudflare Tunnel（免费、自带 HTTPS、免备案）
```bash
# 1. Cloudflare 后台: Zero Trust → Networks → Tunnels → 创建隧道, 记下 tunnel token
# 2. 本机安装 cloudflared 并运行
cloudflared tunnel run --token <tunnel-token>
# 3. 在 CF 后台把隧道公网主机名(如 kefu.example.com)指向 http://localhost:8001
# 4. 域名 DNS 由 Cloudflare 托管, 无需国内备案
```

### 方式三：运营商公网 IP + DDNS（进阶）
向运营商申请公网 IP → 路由器设 DDNS（花生壳/frp）→ 端口映射 80/443 → 电脑。注意：部分运营商封 80/443，需用非标端口或用 Cloudflare 回源。

## 6. 常见问题

- **Redis/Celery 状态**：`/api/v1/system/status` 显示非 ok 说明依赖没跑稳——**这是要修的，不是接受降级**。排查 `systemctl status redis-server fin-agent-worker`；Redis/Celery 常驻后应显示 ok。
- **语义缓存**：SQLite 是主存储；Redis 只做检索结果/任务状态缓存，挂了只是少一层加速，但**正确性不受影响**（这是"降级兜底"的含义，不是运行目标）。
- **模型加载慢**：首次请求触发 bge 加载（约 5-10s），之后常驻；可加 `--workers 1` 避免多进程重复加载。
- **前端 404**：确认 `frontend/dist` 已构建且被 FastAPI 托管（`curl https://域名/` 应返回 HTML）。
- **会话丢失**：多实例部署时需共享 Redis 存会话；单实例无此问题。

## 8. 本机实际部署（2026-08-23 已验证）

本机（Windows）直跑 + Docker 跑 redis 的实际命令：

```bash
# 1) redis (Docker, 镜像源已配)
docker compose up -d redis

# 2) 应用 (宿主机, 用项目 .venv)
PYTHONIOENCODING=utf-8 .venv/Scripts/python -m uvicorn src.api.main:app --host 0.0.0.0 --port 8001 --workers 1

# 3) celery worker (宿主机)
PYTHONIOENCODING=utf-8 .venv/Scripts/python -m celery -A src.celery_app worker --loglevel=warning --concurrency=2

# 4) 公网快速隧道 (Docker cloudflared, 可选)
docker run --rm cloudflare/cloudflared:latest tunnel --url http://host.docker.internal:8001 --no-autoupdate
```

**验证结果**：
- ✅ `/api/v1/system/status`：redis/celery_worker/faiss/model 全部 ok（零降级）。
- ✅ **同一 WiFi 演示**：`http://<局域网IP>:8001`（如 `192.168.1.2`）——聊天正常。
- ⚠️ **trycloudflare 免费快速隧道**：页面/健康检查可访问，但 **LLM 长回答（6-15s）会被免费隧道断开**（uvicorn 已回 200，响应在隧道侧被掐）。公网演示建议：同一 WiFi，或换 cpolar（对长响应更宽松），或 Cloudflare 命名隧道。

> 坑记录：① Docker 拉镜像需国内镜像源（daemon.json `registry-mirrors`），且 auth.docker.io 在本网络不通→基础镜像要直接引用镜像源域名或用 redis 这类小镜像；② Windows 版 cloudflared.exe 在本机无法运行（"无法在此电脑运行"），改用 Docker 跑 cloudflared 容器。
